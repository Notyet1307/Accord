# SAS 对话式事件研判试点

Revision：`SAS-CHAT/draft-2`；日期：2026-09-10。状态：整体方向记录；R004/ADR 与首个本地实现已于用户答复「接受」后生效，其余切片仍为规划。正式边界见 [R004](../product/releases/r004-sas-conversational-agent-pilot.md) 与 [ADR-0004](../adr/0004-sas-conversational-agent-boundary.md)；首个 Accord 实施合同见 [两轮对话 Spec](r004-sas-contact-dialogue.md)，该任务行为以其合同为准。

## 目标与已确认选择

用户在 Accord 的聊天入口中打开固定联系人「事件研判助手」，直接与 SAS 的 `event-triage` 智能体沟通，通过追问、补充材料、只读研判和结果解释完成一件事。

用户明确要求「sas 其中的一个智能体以 accord 中的一个可以直接聊天的对象存在，通过类似 IM 沟通的方式完成任务」，随后以「按照推荐来」确认：首个对象选事件研判助手；全程保持同一可见智能体身份；普通聊天直接回答、缺材料先追问、材料足够后告知并执行只读研判。副作用仍需相应授权与批准。

以下是建议的实施边界和验收合同，不把方案文档中的命令、旧联调授权或本次规划确认转换为新服务运行、发布或生产授权。

## 用户体验与范围

示例：用户说「帮我看下这条告警」→ 助手询问缺少的告警内容与时间范围 → 用户贴入合成材料 → 助手说「材料已够，我开始做只读研判」→ 返回结论、依据和局限 → 用户继续问「为什么这样判断」→ 同一个助手基于该次结果回答。

首版限一个固定联系人、受控非生产用户、私聊、一个进行中的研判 Case。优先接收用户粘贴的合成文本/JSON；不要求用户理解 Case、Run 或内部角色。真实业务数据接入另行明确范围。

普通回复、追问和只读分析不逐条弹批准框。首版不提供扫描、封禁、隔离、删除、自动关单等执行能力；提出此类需求时说明当前能力范围，不能由模型自行批准或执行。

不做群聊、多智能体目录、动态选角、跨会话长期记忆、远端机器、通用 Runtime 平台或五智能体全量集成。

## Owner / Producer / Consumer / Primary seam

| 对象或职责 | 所有者 |
| --- | --- |
| 联系人/App、企业身份、Conversation、原始 Message、消息展示 | MagicChat；复用官方 App 接口，需实际核验联系人入口 |
| 固定 AgentProfile 与 SAS RuntimeBinding、Case、工作流、消息关联、执行接受、响应仲裁 | Accord |
| 事件研判智能体定义、专业回答与追问、SAS Run、Evidence/Finding/Artifact | SAS |
| 人的授权、批准与风险接受 | 实际用户或相应审批人 |

Producer 是已认证的 MagicChat 用户消息及 SAS 结构化输出；Consumer 是 Accord 协调逻辑和原私聊用户。主要跨仓接缝为「Accord 向固定 SAS 智能体提交有界输入，收集带关联身份的结构化结果」。不把 SAS 包装成 Baizhi provider，不让 Accord 的四个旧角色接管专业回答。

建议由 Accord 管理必要的上下文投影和 Case 关联；SAS 处理每次有界贡献。首版不依赖底层 runtime resume，不复制 MagicChat 消息权威，也不自建聊天服务。

## 对话与任务合同（拟议新增）

1. 固定欢迎语可直接返回，不产生付费调用。需要 SAS 作答的实质咨询先创建或关联 Case，再持久接受外部操作；避免任何模型调用绕过 Runtime Operation 规则。
2. 同一件事的追问、补材料、研判和解释沿用同一 Case；普通消息不等于新任务。用户明确开始新事件才新建 Case；无法判断是在补材料还是换事件时先询问。
3. SAS 需新增最小对话贡献合同：输入包括当前消息、受限上下文、材料引用、先前结果引用及冻结版本；结果区分直接回答、需要材料、建议开始研判。最终研判结果沿用 SAS 的结构化结果合同。具体 wire schema 在对应 SAS 任务中固定，不新增通用 session 平台。
4. 对话贡献阶段禁止执行研判工具及外部写入。模型提出“材料足够”仅是候选；Accord 检查范围、已准备输入、权限和重复执行后，接受只读操作并告知用户。真正执行仍通过 SAS Run 接口和 SAS 自身策略校验。
5. 同一 SAS 定义负责专业回答和研判。Accord 可发确定性的开始、失败、等待状态消息，不用另一个模型假扮该智能体。
6. 上下文必须有大小上限、来源、信任标记及明确截断信息；缺失关键材料时追问。聊天和附件内的命令是数据，不会扩大工具权限。
7. 运行中收到补充消息先持久保存，首版串行处理。更改输入会形成新修订；旧结果不可作为新修订的最终答案。必要时询问是否按新材料重新研判，不静默自动追加执行。

## State handoff / Stable identities

- MagicChat conversation/message ID 关联固定 AgentProfile 和 Case；SAS Run ID 只代表 SAS 执行，不替代 Accord Case、Workflow Run 或 Runtime Operation。
- 每次外部调用之前持久化 Operation ID、规范化输入指纹、Case/Workflow/Activity 关联及有效配置版本、上下文版本、预算、deadline、恢复规则。
- 同消息重送不得创建第二次操作。同 Operation ID 同指纹查询/恢复原结果；同 ID 不同指纹拒绝。SAS 未提交的 manual 创建路径已有 compareCreation 指纹检查；新对话调用仍需在固定版本上证明自身具备此合同，不能把 manual 路径的实现直接等同为对话保证。
- 准备好的实际输入字节经校验后冻结，与材料版本及 SAS Run 绑定。输入变化使用新修订和新操作身份，不能覆盖已经接受的输入。
- SAS 结果先作为候选，经 schema、来源关联、Freshness 与 Dedup 校验后进入 Accord 的受控投影。一次用户可见回复只有一个 Response Owner，保留发送与确认关联。

## Failure modes / Recovery behavior

| 情况 | 首版行为 |
| --- | --- |
| 材料缺失、格式错误、超限 | 说明缺项或错误并追问；不启动研判 |
| SAS 不可达或失败 | 原聊天明确报告，保留原 Case 和操作记录 |
| 提交超时、结果未知 | 通过稳定身份查询；不可检索则保持 unknown，不能盲目重跑 |
| 消息重复、结果重复或迟到 | 去重或保留为历史结果，不重复发起研判或发布最终回答 |
| 用户要求停止 | 停止后续工作，调用已有取消接口并报告实际状态；请求已发出不等于取消成功 |
| 越权或副作用需求 | 拒绝执行并说明范围，不转为自动授权 |
| 重启、上下文版本变化 | 从持久状态恢复关联；无法确认的结果不伪装为成功 |

## 建议推进顺序

这只是交付切片建议，不是第二份任务状态表；实际任务状态由各仓 GitHub 所有。每次实施固定一个目标、版本化合同和主要接缝，跨仓变更分开交付。

1. **固定续期边界与 SAS 对话合同。** 将本草案转为有界 Release/ADR 与相应任务合同；SAS 增加回答、追问及研判建议的受限贡献能力。验收：同一定义可进行连续两轮咨询，且对话阶段不能执行研判工具。
2. **Accord 联系人对话切片。** 复用 MagicChat App，接固定 SAS 对象，建立消息—Case—操作关联。验收：用户从可见入口发消息，收到 SAS 回答，补充消息延续同一件事。可用 fake SAS 验证协议，但必须明确标为模拟。
3. **接通材料与真实只读研判。** SAS 侧复用输入闭环既有工作（输入准备/显式提交及独立验收），补齐实际字节与 Run 绑定、冲突检测；Accord 接入这一确定版本。验收：告知开始、只执行一次、返回有依据的结果、继续解释结果。
4. **在同一 IM 闭环上验收恢复与受控真实运行。** 验证重复投递、超时、重启、迟到、停止及权限拒绝，再完成一次授权的合成材料真实试点。真实运行应另行固定配置、输入、版本与运行范围。

输入准备可以与对话切片独立推进，但两者都满足后才能声称“聊天完成真实研判”。不以完整五智能体 qualification 或 R003 全部 crash-window 演练为本试点的默认前置，也不关闭其未完成事项。

## Acceptance tests / Evidence to return

最高验收接缝是用户可见的 MagicChat 私聊全过程；离线测试在其消息入口与 SAS adapter 边界验证相同语义，不只测内部函数。

- 可找到固定联系人，连续咨询和补材料由同一身份回应，不展示轮转角色。
- 缺材料不执行；材料足够且合同校验通过后告知并启动一次只读研判；输入内容可追溯到该次 Run。
- 后续解释引用同次结果；新事件与修订不会被悄悄混入旧任务。
- 重送消息、提交超时、重启和重复结果不会触发未经授权的重复执行；不同输入复用同一身份产生冲突。
- 旧结果不会覆盖新上下文；敏感信息不会串到其他用户或 Conversation。
- 越权需求不能执行；模型输出不能制造批准；取消和失败状态如实可见。
- 真实试点同时保留 UI 对话、输入摘要/哈希、Case/Operation/SAS Run/消息关联、冻结版本及有限执行记录。Mock、真实模型、真实 IM 分开报告。

每个交付 PR 按 delivery gate 绑定精确代码与 Spec 修订、命令/测试、失败恢复结果及未完成项。优先保留这条最小可核验链，暂缓通用证据平台和与本试点无关的完整资格矩阵。

## 待实施前固定的决策

需要一份后续 Release 与 ADR 明确：外部 SAS 边界、普通对话与只读结果的响应规则、有限 Case 生命周期。现有 R003 的固定四角色和最终 Artifact 批准流程继续保持原合同。

具体 schema、输入大小/上下文上限及接口版本由实施前的单项合同固定；不得依赖未验证的 agent-compose 续接能力或把 MagicChat App 的真实可见行为当作已经通过。此草案完成只代表规划完成，不代表这些能力已经存在或验收通过。
