# ADR-0005：R005 候选回复与合成试验信任范围

- Status：ACCEPTED；Revision：r1；2026-09-11。
- Decision owner：产品负责人。
- 接受来源：本会话在基线研究后提出 Q1「候选回答与正式产物」及 Q2「隔离试验中的管理权限」，用户答复「接受你的推荐取舍」。
- 适用范围：仅以下两项 R005 设计取舍。不是 R005 Release 整体接受、实施、部署、外部运行、推送或生产授权。
- 依据：[R005 基线与设计研究](../product/research/r005-baseline-and-design-2026-09-11.md)。外部实现与版本证据由该研究及其第一方引用提供，不以本 ADR 声称接缝已经实现或通过验证。

## 决定

### 1. 候选咨询与正式 Artifact 分开

普通只读咨询可直接返回明确标记的候选回答，不要求逐条事先人工批准；仍须通过身份、授权、来源资格、Freshness、Dedup 和单一 Response Owner 的适用校验。候选答复不是正式接受的证据、合规通过结论或外部业务完成事实。

正式接受或导出的 Artifact 必须由人确认，并绑定精确 revision/digest；内容修订后不能沿用旧确认。模型不能制造批准。具体确认交互、状态转换和验收条件由后续 R005 Spec 固定。

此决定是 R005 的独立选择，不从 R004 的免逐条审批规则推导，也不改变 R003 的批准合同。取舍是避免每条咨询都经过审批，同时保留正式产物的人类接受门。

### 2. 管理权限例外仅限隔离的本机合成试验

原则上接受：在本机、独立、无客户数据的合成试验中，受信 agent-compose daemon 可以持有 Docker 控制权和该隔离 OctoBus 实例的管理级测试 token；guest 的业务能力仍限定为批准的 Search。

管理 token 技术上有写能力，不能因 daemon 只需读取 catalog 就称其为只读凭据。Docker 控制权同样是高权限。guest 不得取得这些权限、上游 token、Docker socket 或直接访问管理面的旁路；隔离是否成立必须实际验证。

该取舍不适用于生产、共享客户实例或真实资料；不选择关闭管理认证，也不授权原生路径失败时自动回退 direct Connect。试验结束后的资源和凭据处置须纳入执行方案；本 ADR 不授权清理无关资源。

## 执行边界与后续

- 保留 R003/R004 的代码、数据库、资格缺项和历史证据，不通过本决定扩张其范围。
- 本机 Docker 只读版本预检已有研究记录；镜像与依赖下载、构建、专用网络/容器/目录创建、Docker socket 授予、Search 服务预置、token 配置及试验执行仍须明确的资源清单和独立授权。
- 后续设计复用 CQA 现有 X1 草稿，不再维护同义生产者 Spec；Accord 自己的消费行为由其版本化 Spec 所有。
- R005 的其余架构、Release 范围、运行恢复合同和资格仍未因此获得接受。实际运行前须按 [Delivery Gate](../agents/delivery-gate.md) 固定合同、版本与证据要求。
