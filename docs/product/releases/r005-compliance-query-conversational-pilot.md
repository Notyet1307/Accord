# R005：固定合规查询智能体的对话接入试点

- Status：ACCEPTED；Revision：r1；2026-09-11。
- Decision owner：产品负责人。
- 接受来源：用户先后选择「接受并实施离线切片」「接受 r3，并实施 Adapter 及其本地协议验证」「采用分层验证」「MagicChat 私聊」「修复并继续测试」「修复协议并继续测试」及「修复并用最后额度验证」。Release 产品决定保持 r1；当前唯一行为合同为 [R005-CQA/r8](../../specs/r005-compliance-query-consumption.md)。
- R005 是当前 Accepted Release。软件范围包含持久消费、受管 Adapter、私聊/正式确认装配和分层本地资格。发布、真实 Runtime/模型/IM、凭据及资源操作仍依据消费合同第 9 节引用的独立用户授权和实际记录；不是生产或 CQA/平台修改许可。R003/R004 边界与历史证据不变，X1 一次性授权不转移。

## 产品承诺

一个受控用户通过 MagicChat 官方 App 私聊固定「合规资料研究员」，补齐问题及查询范围后，在同一 Case 内收到带引用、缺项和局限的候选答复；需要正式接受或导出时，用户确认精确 Artifact 修订，Accord 才交付。

首个数据范围是明确标记 synthetic 的单份等保测试文档。模型回答必须使用 CQA 交付并验收的受管原生模型组合及本次获准运行配置；不能把 X1 的提取答复与另一个候选的模型试验拼成完成证据。测试标记始终可见，不声称现行法规资格、真实企业合规通过或其他四域覆盖。

## 有界范围

- 一个固定 CQA Profile/RuntimeBinding，一个受控用户及私聊，一个活动 Case；串行查询，明确结束后才能建立下一 Case。
- Accord 使用已选定的 TypeScript/Node.js；本试点采用独立单进程 SQLite/WAL，持久接受后才准备外部输入并提交运行。R003/R004 代码、库和执行记录不变，不能同时协调同一 Conversation。
- CQA 保持独立 producer，负责资料筛选、引用与生成；agent-compose 保持运行事实所有者，OctoBus 负责被授权的知识查询。Accord 不复制其数据库、检索或模型实现。
- 补字段、状态通知、引用展示采用确定性逻辑，不增设另一个模型代写专业答案，不要求 CQA 接受一个不存在的聊天历史字段。
- 候选内容、业务接受与用户可见回复分开；同消息重放不重复执行，同结果重放不重复接受/发送。正式 Artifact 继续遵守已接受的 ADR-0005。
- 单次授权固定主体、输入/资料范围、运行与生成配置、期限和调用范围。模型用量可记录但不冒充预算闸门或完整账单；UNKNOWN 不自动重跑，取消请求不冒充远端停止。

不包含客户资料、真实法规库验收、RAG、上传、知识库编辑、扫描或其他业务写入、群聊、动态 Agent 市场、多 Runtime、多租户/副本、跨机器恢复、Lody/ACP、生产部署或通用任务平台。

## 成功与失败判据

成功必须来自真实私聊和同一冻结生产者组合：用户提问 → 缺字段时追问且无外部查询 → 补齐后持久 Operation → 真实受管 CQA 模型候选 → 来源和当前上下文校验 → 原会话唯一回复；请求正式产物时还须完成精确人工确认与交付。

无依据/待复核应明确显示未解决项；旧上下文结果、重复/错绑结果、未知执行和发送确认丢失不能被显示为成功。只有 CLI 成功、技术接缝提取答复、离线模拟、X1 通过或单独模型试验通过，均不足以证明本 Release 完成。

逐项行为、失败和验收由 [R005-CQA/r8](../../specs/r005-compliance-query-consumption.md) 的 C01–C20 所有，不在本 Release 复制第二份矩阵。软件交付不缩减完整 Release 要求。

## 承接、并行与准入

1. 本 Release 和 [ADR-0006](../../adr/0006-r005-compliance-query-consumer-boundary.md) 的已接受决定不变；当前获准软件范围包括私聊装配。每次仍按 Delivery Gate 固定一个主 Owner／主接缝。
2. CQA 已交付并获接受的 S2 查询／synthetic 草稿切片由消费合同第 8 节固定，G1／G2 仅继承该组合的有界资格。CQA 保持单写者；Accord 不重复要求生产者交付已完成查询，也不改写原真实资料 AC。
3. G3 同宿主持久完成结果重放由用户延期，按消费合同第 9 节保留为后续部署可靠性验收，不阻塞当前查询切片；持久挂载预检和 UNKNOWN 不新建替代 Run 的保护不变。
4. 真实受管查询接缝须另获运行授权并证明输入／控制／输出事实，再接私聊／正式确认。按需 extractive 接缝不替代模型目标；分阶段准入以消费合同第 9 节为准，软件切片或旧生产者试验通过均不能标整个 Release 完成。

Accord 不接管另一会话的 CQA 开发，不要求等待 RAG 或整个知识产品完成。真实部署/网络、资料/模型外发、MagicChat 和清理范围必须按各自执行清单批准；本轮不建立第二份 X1 资源表或恢复已停止环境。

## 权威与未决边界

[ADR-0002](../../adr/0002-production-coordination-runtime-language.md) 的协调语言、[ADR-0005](../../adr/0005-r005-candidate-response-and-trial-trust.md) 的候选/正式产物决定，以及 ADR-0006 的独立存储、控制通路与恢复边界已接受。Release 接受不是运行验收；新增执行事实仍须来自明确授权及实际执行记录。
