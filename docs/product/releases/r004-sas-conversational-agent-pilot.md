# R004：SAS 对话式事件研判试点

- Status：ACCEPTED；Revision：r1；2026-09-10。
- Decision owner：产品负责人。
- 用户来源：确认一个 SAS 智能体作为可直接聊天的对象存在，选择固定 event-triage、同一身份、多轮沟通完成只读任务，并要求继续规划。
- 2026-09-10 用户答复「接受」，接受本 Release、ADR-0004，并授权首个对话切片本地实现。R004 为当前增量；R003 保持其历史合同，不声称本 Release 已验收，不授权真实服务、推送或生产动作。

## 产品承诺

受控非生产用户从 MagicChat 官方 App 聊天入口打开「事件研判助手」，与同一个 SAS 智能体连续沟通：提问、补充合成材料、收到只读研判结果、追问依据。用户无需操作 Run 表单或辨识后台角色。

最小闭环：私聊消息 → Case 关联 → SAS 回答或追问 → 材料准备与冻结 → 告知开始并接受只读执行 → SAS 结果 → 原私聊解释与后续沟通。

## 有界范围

- 一个固定 App/AgentProfile/SAS event-triage 绑定，一个受控用户及私聊，一个进行中的 Case；允许明确结束后开始新 Case。
- Accord 继续使用 TypeScript、单进程 SQLite/WAL；SAS 保持独立部署和自有存储。只通过版本化接口集成。
- 有界文本/合成 JSON 输入；SAS 专业回答不经过 R003 四角色链。普通聊天、追问及只读结论不要求逐条 Human Approval。
- 所有外部计算仍先持久接受，响应仍受 Freshness、Dedup 与单一 Response Owner 控制。侧效应业务操作不在首版范围。
- 保留最低输入来源、版本、Operation、SAS Run 和消息关联；不以通用证据平台或五智能体全量 qualification 为默认前置。

不包含生产数据、业务写入、扫描或攻击验证、群聊、动态选角、跨会话长期记忆、Lody/ACP、通用运行平台、多租户或多副本生产化。

## 成功与失败判据

成功是用户在真实私聊中通过至少一次追问补材料完成只读研判，再追问结果，始终面对同一个智能体；实际输入可关联到真实 SAS 执行，重复消息不导致重复执行或回复。

仅接口通、Mock 回复、模型自行声称读取材料、终端 Run 成功、旧 R003 联调通过均不足以证明此 Release 完成。未知执行结果不得显示成功，旧输入结果不得当作新任务结论。
